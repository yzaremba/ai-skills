How you work with it

  1. Talk to the Manager. It dispatches the role that owns the work, prints each question that role has for you word for word, and sends your answer back. On Claude Code you may also type in a dispatched role's thread.
  2. You never have to load a role. Loading the Product Manager or the Architect into your own session (/architect, $architect) is an option; on Claude Code, only in a session not started as the Manager.
  3. One review per document, by another role. The Manager sends a PRD or charter to the Idea Reviewer and a PLAN to the Plan Reviewer before its gate; the IM sends code to the Code Reviewer.
  4. Coders in parallel only where the PLAN marks a group, each in its own worktree, at most roles.max_parallel_coders (3) at once.
  5. Commits you ask for: the Manager commits the files it moved or a role wrote and reported, each by name.
  6. STATE carries the sprint. Any session, on either provider, picks a sprint up from its docs and STATE.
  7. Lessons at the close. Proposed with the Ready commit, written to the project memory only when you approve them.

One word closes a sprint

"close it" →Ready commit →merge →suite →cleanup →archive + commit

Stops only on trouble. A push is a word of its own.
