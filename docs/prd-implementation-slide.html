Gate“close”

Close

Done

Finished, or code-complete: steps that only wait become D-items.

Ready commit → merge → full suite → remove worktree & branch → archive + commit

DONE/

lessons proposed; written only if approved

  • One word per gate. “close” covers the whole close and stops only on trouble: a conflict, a failing suite, a removal that needs force.
  • Commits: the start commit; before the build, each commit on request; then the chosen cadence; then the close. Any push, and removing unmerged work, is always a separate decision.
  • Abandon or supersede at any stage, on the user's decision: open lines skipped, docs archived to DONE/, no work removed.
