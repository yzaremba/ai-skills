# The outcome, and nothing beyond it

**Recorded:** 2026-10-19, after sprint 92 of a project that uses the framework
**Roles:** all, and whoever writes role or process text, or works in this repository

## What

Build what the user's stated outcome needs and nothing that proves, records or guards it, unless the user asks: no harness, proposal document, receipt, ledger, evidence archive, hash list or extra review. Any increase of scope is put to the user as one, with what it costs and what it buys, and cutting is always on offer. This holds for this repository's own work too: a change here is the smallest that meets the ask, and tooling, tests of the tooling, manifests, documents and slides grow only when the user asks for them.

## Why

Sprint 92 was "a GitHub Actions runner on the research VPS". Its PRD grew to 13 requirements with a live proof program for acceptance, its PLAN to 1,858 lines and 38 steps, and after ten days and most of the tokens the runner had never run a job: the verification phase was building its own controller, ledger and health sampler to run the test suite once in a sandbox, and one contract document went through three review rounds in a day. Every review finding was right and none moved the runner toward a job. The user noticed the drift three times; each time the agents agreed and produced more plan, because nothing in the process asked whether a step was worth its cost.

## When it applies

Writing a PRD, a PLAN or a review; reporting a stop with options; deciding whether to add a test, tool, check, document, proof or review anywhere, this repository included.
