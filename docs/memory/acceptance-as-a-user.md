# Run acceptance sessions the way a user would; friction is a finding

**Recorded:** 2026-10-16, sprint 01
**Roles:** all (whoever plans or reviews an acceptance run)

## What

An acceptance run of the workflow passes only if a user could work it without knowing the rules by heart. Drive it as a user would, from the Manager, and record every point where the user had to remember a rule, switch roles by hand, repeat an approval or wait for a needless spawn, as a finding to fix, even when the PLAN's checklist passes.

## Why

In sprint 01 the sample sprints met their checklist (every role on both providers, gates passed, documents correct) while the user found the workflow clunky: loading roles by hand on Codex, "back to the Manager" for every gate, a re-approval caused by approval prose in a PRD, a four-round close. Decision U came from the user's reaction, not from the checklist.

## When it applies

Planning, running or reviewing an acceptance or sample sprint, and any change to the roles, the gates or the close.
